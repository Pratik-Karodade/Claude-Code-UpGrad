# Contract: Chat API

**Feature**: [spec.md](../spec.md) | **Plan**: [plan.md](../plan.md) | **Date**: 2026-11-14

Single endpoint for the MVP. No authentication. Base path: `/api`.

## POST /api/chat

Sends one user message and streams the assistant reply.

### Request

- **Headers**: `Content-Type: application/json`, `Accept: text/event-stream`
- **Body**:

```json
{
  "conversationId": "3f2c9a1e-7b4d-4e8a-9c21-5d6e7f8a9b0c",
  "message": "Why am I getting a 429 error?"
}
```

| Field | Required | Rules |
|---|---|---|
| `conversationId` | yes | UUID v4 string. Generated by the client per chat. |
| `message` | yes | 1 to 2,000 characters after trimming whitespace. |

### Pre-stream responses (no SSE started)

| Status | When | Body |
|---|---|---|
| `400 Bad Request` | Missing or invalid `conversationId`; empty message; message over 2,000 characters | `{ "code": "VALIDATION_ERROR", "message": "<user-facing text>", "requestId": "<id>" }` |

### Streaming response

- **Status**: `200 OK`
- **Content-Type**: `text/event-stream`
- **Sequence**: zero or more `token` events, then exactly one terminal event (`done` or `error`).

Example:

```text
event: token
data: {"text": "A 429 means "}

event: token
data: {"text": "you have hit a rate limit..."}

event: done
data: {"requestId": "req_7f3a", "escalation": false, "latencyMs": 1834}
```

#### Event: `token`

| Field | Type | Notes |
|---|---|---|
| `text` | string | Non-empty fragment of the reply. Concatenate in order. |

#### Event: `done`

| Field | Type | Notes |
|---|---|---|
| `requestId` | string | Matches the server log entry. |
| `escalation` | boolean | `true` when the reply includes a referral to human support. The UI may highlight it. |
| `latencyMs` | integer | Total server-side time from request receipt to completion. |

#### Event: `error`

| Field | Type | Notes |
|---|---|---|
| `requestId` | string | For support reference. |
| `code` | enum | See error codes below. |
| `message` | string | User-facing, friendly text. Never raw provider text. |

### Error codes

| Code | Trigger | Suggested user message (UI may localize) |
|---|---|---|
| `VALIDATION_ERROR` | Pre-stream 400 | "Please enter a message of up to 2,000 characters." |
| `RATE_LIMITED` | Provider rate limit or quota | "We're receiving a lot of requests right now. Please try again in a moment." |
| `PROVIDER_UNAVAILABLE` | Provider 5xx, connection failure, or timeout | "The assistant is temporarily unavailable. Please try again shortly." |
| `INTERNAL` | Any other server failure | "Something went wrong. Please try again." |

Network failures in the browser (no response at all) are detected by the client and shown as
"Connection lost. Check your internet connection and try again." They are not returned by this API.

### Behavior notes

- Each request appends the user message and, on completion, the full assistant reply to the
  `conversationId` window. A reply that ends in `error` is not stored in the window.
- The client MUST NOT send system prompts or assistant turns. Only `conversationId` and `message`
  are accepted.
- Requests for an unknown `conversationId` start a new window; there is no 404 case.

## CORS

- Allowed origin: the value of `caramel.chat.cors-allowed-origin` (default
  `http://localhost:5173`). No wildcard.
- Allowed methods: `POST`. Allowed headers: `Content-Type`, `Accept`.
- No credentials are sent (no cookies or auth headers in MVP).

## Versioning

MVP contract, unversioned. Any change to event names, fields, or error codes is a breaking change
and requires updating this file and `frontend/src/types/chat.ts` in the same change.
